# Project Spec: `yeGPT` - A Character-Level GPT Trained From Scratch on Kanye West

> **Working document for Claude Code.** This is a learning project. The goal is to
> *understand how a transformer language model works from the ground up* by building
> one directly on PyTorch primitives - no `transformers`, no pretrained weights, no library magic for the
> model itself. The corpus is Kanye West text (lyrics + interview/rant transcripts +
> tweets) because the voice is distinctive enough that even a tiny half-trained model
> produces recognizable output, which maximizes learning-signal-per-hour.

---

## 1. What We're Building

A minimal decoder-only transformer (GPT architecture), character-level tokenization,
trained with next-token prediction on a Kanye corpus the author assembles. Followed by
a sampling script to generate text from any checkpoint and watch the style emerge.

The architecture is deliberately the nanoGPT-class design: token + positional
embeddings → N transformer blocks (causal multi-head self-attention + MLP, each with
residual connections and LayerNorm) → final LayerNorm → linear head to vocab logits.

## 2. Tech Decisions (locked, with rationale)

| Decision | Choice | Why | Revisit if |
|---|---|---|---|
| Tokenizer | Character-level | Kanye text is slang/ad-lib/punctuation chaos; char-level handles it without vocab engineering and keeps the project simple & fully readable | Output too coarse and you want to scale up later |
| Model size | ~10M params (start smaller, ~1-3M, to first prove the loop) | Fits 4080 trivially, iterates in minutes, big enough to show style | After loop proven, scale toward 10M for better output |
| Framework | PyTorch (tensors/autograd/optim only) | Industry standard, lets us implement the model ourselves without reimplementing backprop | - |
| Precision | bf16 mixed precision | 4080 supports it, ~halves memory, speeds training | OOM or instability |
| Context length | Start 128, target 256 chars | Small enough to train fast, long enough to capture line/bar structure | - |
| Param mgmt | `pyproject.toml`, `uv` or `pip`, no notebook | Author prefers modern Python layout, reproducibility | - |
| Config | A single typed `dataclass` (`TrainConfig`), no global state | DI over globals; one place to tune | - |

**Typing/style:** Strict PEP 484, no `Any`, `Final`/`Literal` where they add signal.
PEP 8. Small modules over one monolith. Code-first, minimal prose, comments only where
intent isn't obvious from the code.

## 4. Data Contract (critical - gate before training)

**Claude supplies the raw text.** and also Claude builds the pipeline that ingests whatever lands in `data/raw/`.

`data_prep.py` must:
1. Read all `.txt` in `data/raw/`.
2. Normalize: strip metadata lines (e.g. `[Verse 1]`, `[Chorus]`, song titles, URLs,
   `@handle` artifacts), collapse repeated blank lines, normalize unicode quotes/dashes.
3. Concatenate into `data/corpus.txt`.
4. **Report total characters and MB, and PRINT A WARNING IF UNDER ~1MB.** Below ~1MB a
   from-scratch char model memorizes rather than generalizes. This is a gate: the author
   should clear ~1MB (lyrics alone ≈ 0.5–0.7MB, so transcripts + tweets are needed) before
   committing to a real run.

**Expected corpus characteristics to state up front:** single-voice, mixed register
(rapped bars + spoken stream-of-consciousness + short tweet bursts), heavy slang,
chaotic punctuation. The mix is a feature - it's what makes the voice recognizable.

## 5. Tickets (work order - do these in sequence)

> Each ticket: implement, write its test where applicable, confirm it runs, then stop
> for author review before the next. Ticket-by-ticket is the explicit working style.

### TICKET-01 - Project scaffold
`pyproject.toml` (deps: `torch`, dev: `pytest`, `ruff`, `mypy`), repo tree, `.gitignore`
(data, checkpoints, `__pycache__`), stub `README.md`. Verify `uv sync` / `pip install -e .`
works and an empty `pytest` run is green.

### TICKET-02 - `config.py`
A single frozen-ish `TrainConfig` dataclass: vocab_size (filled at runtime), n_layer,
n_head, n_embd, block_size, dropout, batch_size, lr, max_iters, eval_interval, device,
seed. Typed, documented defaults sized for the 4080. No globals.

### TICKET-03 - `data_prep.py`
Per the Data Contract (§4). Must print char count + MB + the sub-1MB warning. Idempotent.

### TICKET-04 - `tokenizer.py` + test
Char-level: build sorted vocab from corpus, `stoi`/`itos`, `encode(str)->list[int]`,
`decode(list[int])->str`. Test: round-trip `decode(encode(s)) == s` for sample strings.

### TICKET-05 - `dataset.py` + test
Load `corpus.txt`, encode to a tensor, train/val split (e.g. 90/10), `get_batch(split)`
returning `(x, y)` of shape `(batch_size, block_size)` where y is x shifted by one.
Reproducible via seed. Test: shapes, dtypes, and that y is x shifted by one.

### TICKET-06 - `model.py` (the core) + test
Implement, as readable separate `nn.Module`s:
- `Head` - single causal self-attention head (Q/K/V projections, scaled dot-product,
  causal mask via `tril`, softmax, weighted sum). **Implemented manually**, not
  `nn.MultiheadAttention`.
- `MultiHeadAttention` - N heads in parallel + output projection.
- `FeedForward` - the MLP (linear → GELU → linear), expansion factor 4.
- `Block` - attention + FFN with **pre-norm LayerNorm and residual connections**.
- `GPT` - token embedding + positional embedding → blocks → final LN → lm_head;
  `forward(idx, targets=None)` returns logits and (optional) cross-entropy loss;
  `generate(idx, max_new_tokens)` autoregressive sampling.

**Claude must explain each component in plain terms as it's built** - what attention is
doing, why the causal mask, why residuals/LayerNorm, what positional embeddings buy us.
This explanation IS the deliverable as much as the code. Test: forward pass produces
correct logits shape `(B, T, vocab_size)`; loss is a scalar; `generate` extends a seed
without crashing.

### TICKET-07 - `train.py`
Training loop: AdamW, bf16 autocast, periodic train/val loss eval, checkpoint saving,
seed set for reproducibility. Prints loss curve to stdout. Small default `max_iters` so
first run finishes in minutes on the 4080. Must run end-to-end on a tiny corpus.

### TICKET-08 - `sample.py`
Load a checkpoint + tokenizer, generate N characters from an optional seed prompt,
print. This is where the author watches noise → word-shaped → Kanye-shaped.

### TICKET-09 - First real training run + iterate
Run on the real corpus. Observe. Tune `n_layer/n_head/n_embd/lr/block_size`. Document
what changed the output. Expected end state: recognizably-Kanye gibberish. Capture a few
sample outputs in the README as a before/after.

### TICKET-10 (stretch) - Scale & ablate
Push toward ~10M params, longer context, compare. Optionally try word/BPE tokenization
and contrast with char-level. Note where the 4080 caps out.
